# 独立深度研究工作台 · 产品全景解读

> 版本:v1.0(2026-09) · 单机单用户 · 浏览器 + 本地服务 · 品牌研究 × 行业研究
> 一句话定位:**把"多智能体深度研究"装进一台个人电脑——输入一个研究目标,产出一份每个结论都能点开看到原始证据、每条数据都带口径、每次发布都可追溯的研究报告。**

---

## 第一部分 前端:用户能看到、能操作的

### 1. 怎么启动

双击仓库根目录的 **`启动深度研究.command`**,它会自动完成:

1. 拉取远端共享数据(双机同步,见 §6);
2. 构建前端与后端;
3. 在本机 `127.0.0.1:4173` 启动服务;
4. 自动打开浏览器进入工作台;
5. 关闭终端/退出时自动把本地新数据回推远端。

全程无需命令行知识。界面上你可以看到的应用名是 **「独立深度研究」**,副标题"品牌 × 行业研究工作台"。

### 2. 页面地图

| 页面 | 路由 | 你在这里做什么 |
|---|---|---|
| 研究项目 | `#/` | 浏览/新建研究项目,看每个项目的运行数、快照数 |
| 项目工作台 | `#/project/:id` | **核心页**:发起运行、看进度、读报告、发布版本 |
| 设置 | `#/settings` | 调整默认模型供应商与资源预算 |

界面基于 antd 6 + 棱镜设计语言(Prism):左侧固定侧边栏导航,右侧主工作区由若干带标题与说明文字的面板(Section)组成,状态用彩色徽标(Pill)表达(进行中/已完成/已取消/失败/有限交付)。视觉与 trade-area 项目同源。

### 3. 研究项目列表页

- **能看到**:项目卡片列表——名称、模块类型(品牌研究/行业研究)、研究目标、历史运行数量、证据快照数量。
- **能操作**:
  - **新建项目**:选择模块(品牌/行业),填写研究目标与范围(如"森马,近三年经营与品牌运营情况"),即刻创建;
  - 点击任一项目进入工作台。

### 4. 项目工作台(核心页)

#### 4.1 新建研究运行——"计划 → 框架 → 执行"三步确认

1. 点击发起运行,系统调用大模型生成一份**研究计划预览**(围绕你的目标拆解出研究问题清单,按模块的问题框架组织,如品牌模块覆盖定位/价格/渠道/竞品);
2. 计划不是黑盒:**问题清单可直接编辑**——删掉不关心的、改写表述;
3. 下一步生成**报告框架预览**(标题、副标题、分节、每节目的与内容要点),同样可增删改;
4. 确认框架后才真正开始执行——草稿与正式报告都按这份确认的框架组织;
5. 发起时采用适中默认预算(**8 次搜索 / 12 次抓取,全程约 10 分钟**),也可按 run 覆盖。

#### 4.2 当前运行——进度全程可见

- 顶部四张指标卡:状态、搜索次数、抓取次数、预估成本;
- **六阶段步骤条**:计划 → 采证 → 分析 → 草稿 → 评审 → 发布,每个阶段完成即点亮,采证阶段每答完一个问题都会刷新用量(页面每 2.5 秒自动轮询);
- **可随时取消**:点取消按钮即中止,已完成的阶段成果保留在检查点里;
- 运行启动的瞬间就有"进行中"记录——即使服务被中断,也不会出现"无痕消失"的运行。

#### 4.3 运行记录——恢复与发布

- 每次运行留下一条记录:状态(进行中/已完成/已取消/失败)、所处阶段、用量(搜索/抓取/成本/耗时);
- **取消的运行可恢复**:自检查点续跑,不必从零重来;
- **完成的运行可发布**:一键把结果固化为不可变版本。

#### 4.4 报告阅读(草稿)——结论与证据逐条挂钩

- 运行产出的报告标记为**草稿**:完整 Markdown 排版(标题分级、表格、引用块),报告主体 + **主张核查表**:每条事实主张一行,标注核查状态(已核查/未核查)与命中情况;
- **点击任一主张,右侧滑出证据抽屉**:直接显示该主张来源页面的净化正文快照,引文在快照里高亮可寻——"这句话到底从哪来的"一眼可验;
- 报告附**限制披露**:哪些问题只得到部分回答、哪些主张因证据不足被降级为"未核查",全部明说,不冒充完成。

#### 4.5 版本与正式报告——发布即不可变,定稿多格式

- 每次发布生成 `v1 / v2 / v3…` 不可变版本,记录差异摘要(对比上一版改了什么);
- 确认草稿后点击**「生成正式报告」**:按已确认的报告框架装配定稿——封面、元信息条、目录、摘要卡、分节(要点提炼 + 正文/表格)、主张核查表、限制披露、来源清单;
- **三种正式格式**:**HTML**(新窗口浏览)、**PDF**(打开即打印页,存为 PDF)、**PPTX**(封面/摘要/分节/核查统计,16:9 可直接演示);
- **导出**:一键下载 ZIP(草稿 md/html、结构化 manifest、证据快照全文,含已生成的正式报告)。

### 5. 设置页

- **模型供应商**:查看/设定主备链路的首位模型(如 `minimax-cn / MiniMax-M2.7`;备用链在服务端维护,见 §9);
- **默认预算上限**:默认最大搜索次数与最大抓取次数,作用于之后的每次运行;
- 密钥类字段**永远不可见也不可写**——设置接口会主动剥离/拒绝任何疑似密钥的字段(见 §15)。

### 6. 双机数据共享(macmini + MacBook)

研究数据存放在仓库内的 `research-data/` 目录,通过 git 通道在两台机器间自动同步:

- 每次运行结束,服务端自动 commit + push;
- 启动器启动时先 pull、退出时再 push;
- 你在 MacBook 上建的项目、跑的报告,回到 macmini 打开启动器就能看到,反之亦然;
- 同步冲突时保本机数据、中止远端合并,绝不丢数据。

## 第二部分 后端:用户看不到的底层架构

### 7. 总体架构

```
浏览器 (React 19 + antd 6, HashRouter)
   │  HTTP (仅 127.0.0.1:4173)
   ▼
本地服务 (Node http, src/server/server.ts)
   │  静态托管 ui-dist + JSON API
   ▼
研究编排器 (src/core/runResearch.ts, ~600 行,唯一入口)
   │
   ├─ 模块层  src/modules/{brand,industry}.ts   问题框架/大纲/模块检查
   ├─ 质量层  src/quality/*                     引用核查/口径检查/模块质检
   ├─ 存储层  src/stores/fsStore.ts             文件系统项目存储
   ├─ 发布层  src/app/{projectService,exportBundle}.ts
   │
   ▼ 适配器边界(一切外部依赖从这里出去,可录制/回放)
┌─────────────────────────────────────────────┐
│ LLM 主备链: MiniMax-M2.7 → Xiaomi MIMO 2.5 Pro │
│ 搜索双链:   MiniMax MCP → Xiaomi websearch      │
│ 抓取解析:   HTTP 抓取 → 正文抽取                │
└─────────────────────────────────────────────┘
```

设计基调:**编排器不含任何外部调用**,所有网络依赖(模型/搜索/抓取)都收敛在适配器层——这是整个系统可测试、可回放、可换供应商的根基。运行时通过 pi SDK(`@earendil-works/pi-ai` + `pi-agent-core`)进程内接入 LLM,**不走 CLI 子进程**。

### 8. 研究流水线(核心编排)

`runResearch` 是全系统唯一的研究执行入口,六阶段顺序推进,每个阶段完成后落**检查点**:

| 阶段 | 干什么 | 关键机制 |
|---|---|---|
| 1 计划 | 目标 → 研究问题清单(按模块问题框架) | 用户可带确认过的计划进入,跳过再生成 |
| 2 采证 | 每个问题:搜索 → 选源 → 抓取 → 快照 → 抽取事实主张 | 预算按剩余问题均分;附件可预先注入快照 |
| 3 分析 | 主张聚合、冲突发现、缺口识别 | 只基于已核实证据,不外推 |
| 4 草稿 | 证据 → 结构化报告草稿(按模块大纲) | JSON 解析失败自动降级为裸 Markdown 兜底 |
| 5 评审 | 逐条核查引用、检查数值口径、模块质检 | 修复循环,不合格打回 |
| 6 发布 | 通过门禁 → 不可变版本;证据不足 → **有限交付** | 命中率 ≥80% 正常交付,否则降级披露 |

贯穿全程的三条硬原则:

- **执行完成 ≠ 证据充分**:阶段输出经 zod `safeParse` 护栏——模型输出不合格就取缺省值并把限制写进披露,**绝不击杀整个 run,也绝不编造补齐**;
- **预算即边界**:搜索/抓取/成本/时长都有上限,超了就停止采证带着已有证据进入下一阶段(capped 状态如实记录);
- **检查点续跑**:取消/中断后自最近检查点恢复,不重复消耗。

### 9. 多智能体与模型主备链路

阶段工人 = pi-agent-core 的进程内 agent loop,每个阶段(计划/分析/草稿/评审)是一次独立的模型会话,采证阶段的"阅读"由抽取工人承担(从网页快照中提取≤80字带原文引文的事实主张)。

模型链路**(主备+熔断)**:

```
minimax-cn / MiniMax-M2.7   ←—— 首选
   │ 429/402/quota/5xx/超时/连接重置…
   ▼ (瞬时故障判定 isTransientProviderError)
xiaomi-token-plan-cn / mimo-v2.5-pro  ←—— 备用顶上
   │ 连续 2 次瞬时失败
   ▼
熔断:冷却 10 分钟,期间直接走备用,不空耗重试
```

工程细节(全部来自实测踩坑):

- **快速失败**:`maxRetries: 1`,把重试决策交给自己的主备逻辑,不让 SDK 内部重试吃掉超时预算;
- **超时 300s**(可用 `DR_MODEL_TIMEOUT_MS` 调):备用模型推理慢,实测单次抽取最长 199.5s,150s 不够;
- **错误不吞**:agent loop 会把供应商 429 吞进消息(`stopReason=error`)而不抛异常——适配器主动检出并转抛,备用链路才会真正生效;
- **MIMO 无视 system 通道**:所有指令并入 user 消息发送,两个供应商均兼容。

### 10. 证据采集:双搜索链 + 抓取解析

- **搜索主链**:MiniMax MCP 服务(`uvx minimax-coding-plan-mcp`,stdio **NDJSON** 帧协议,非 Content-Length;工具失败文本显式抛错;关闭时杀整棵进程树防孤儿挂管);
- **搜索备链**:Xiaomi websearch(`tools:[{type:"web_search"}]`,结果从 `annotations.url_citation` 提取);
- 主链配额耗尽/失败自动切备链,对编排器完全透明;
- **抓取**:按 URL 拉 HTML → 正文抽取 → 存**纯文本快照**(原始 HTML 永不落盘、永不下发);
- 快照是证据的唯一形态:引用核查、证据抽屉、导出报告全都对齐到同一份快照文本。

### 11. 质量与发布门禁(7 项横向控制的产品化落点)

三道纯函数检查器(`src/quality/`,无 IO、全单测覆盖)+ 一道发布决策:

1. **引用核查** citationVerifier——每条主张的引文必须能在来源快照正文中找到(去全部空白归一后做连续子串匹配,防排版差异误杀);
2. **口径检查** calibrationChecker——数值主张必须带单位口径,单位归一(如"万亿元人民币"≡"万亿元"),防口径歧义;
3. **模块质检** moduleCheck——报告必备章节齐全、问题主题全覆盖、数值带口径、事实有证据挂接;
4. **发布决策**——事实主张命中率 ≥80% → 正常交付;<80% → **有限交付**(报告照给,限制披露置顶);核查失败的主张降级为 `unverified` 留在报告里,**不删除也不冒充**。

### 12. 可靠性机制

- **启动即落记录**:POST /runs 先写一条 running 记录再启动编排,进程中断也有痕;
- **僵尸清扫**:服务启动时把上次遗留的 running 记录统一标记为 failed("服务中断"),状态永不悬挂;
- **失败落档**:run 抛错不冒充完成,落 failed 记录带错误信息;
- **阶段实时落盘**:每个阶段推进、采证每答一问,run 记录即写盘,前端轮询看到的是真实进度;
- **检查点恢复**:POST /runs/resume 读回原请求,自检查点续跑。

### 13. 数据模型与存储布局

三大契约由 zod schema 严格定义(`src/contracts.ts`):`ResearchRequest`(研究请求)/ `ResearchRun`(运行记录)/ `ResultBundle`(结果包)。文件系统即数据库:

```
research-data/
└── projects/<项目id>/
    ├── project.json          # 项目元信息(模块/目标/范围)
    ├── snapshots.json        # 证据快照索引(正文为纯文本)
    ├── audit.jsonl           # 审计日志(append-only)
    ├── requests/<请求id>.json # 研究请求(恢复运行用)
    ├── runs/<runId>/run.json # 运行记录 + 检查点
    └── reports/v<N>/         # 不可变发布版本(bundle.json + 导出物)
```

整个 `research-data/` 同时是一个 git 工作副本,这就是双机共享的全部机制——同步=add→commit→pull --rebase --autostash→push,冲突时 abort 保本机。

### 14. 本地服务与 API

纯 Node `http` 服务,只绑 `127.0.0.1:4173`,同时静态托管前端产物:

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/projects` | 项目列表 |
| POST | `/api/projects` | 新建项目 |
| GET | `/api/projects/:id` | 项目详情(meta + 运行 + 快照) |
| POST | `/api/projects/:id/plan-preview` | LLM 生成研究计划预览 |
| POST | `/api/projects/:id/outline-preview` | LLM 生成报告框架预览(供用户确认) |
| POST | `/api/projects/:id/runs` | 发起运行(立即落 running 记录) |
| POST | `/api/projects/:id/runs/cancel` | 取消运行 |
| POST | `/api/projects/:id/runs/resume` | 自检查点恢复运行 |
| POST | `/api/projects/:id/publish` | 发布不可变版本(含差异摘要) |
| GET | `/api/projects/:id/versions/:v/bundle` | 取指定版本结果包 |
| POST | `/api/projects/:id/versions/:v/formal` | 生成正式报告(LLM 摘要,不合格走确定性兜底) |
| GET | `/api/projects/:id/versions/:v/formal/{html,pptx,json}` | 下载定稿产物 |

| GET/PUT | `/api/settings` | 读写设置(密钥字段强制剥离/拒绝) |

### 15. 安全与权限控制

- **密钥只走环境变量**:由 `scripts/with-minimax-env.sh` 从本机凭据库(MiniMax 取 `~/.pi/agent/auth.json`,小米取 `~/.zcode/v2/config.json`)静默注入进程,**不打印、不落仓、不进日志、不进报告**;
- **服务只听本机回环**:127.0.0.1,外部网络不可达;
- **设置 API 防密钥回传**:任何疑似 key 的字段一律剥离/拒绝;
- **快照净化**:只存/只发纯文本正文,来源 HTML、脚本、内联资源永不落盘永不下发;
- **导出转义**:HTML 报告全文转义,证据文本无法注入标记。

### 16. 测试与可回放架构

适配器边界天然是个"录制/回放"缝:live 适配器可**录制**每次真实外部调用(模型/搜索/抓取/阶段)为夹具,测试时用 **replay** 适配器按调用键(由 requestId 派生,跨 run 稳定)原样回放——离线测试跑的是真实供应商的响应形状,而非手写 mock。当前 **81/81 测试(21 个文件)全绿**,覆盖:引用核查归一、口径单位归一、主备切换与熔断、搜索主备与 NDJSON 帧、阶段护栏降级、检查点、发布与导出、数据同步冲突。
