## Red-Team: 独立深度研究工作台第一期(品牌研究 × 行业研究,独立运行、证据可追溯)

评估对象:`.flow/proposal.md`(产品方案 v1.0,2026-09-20)。
结论:**go**。当前没有任何 kill 判据已被满足;以下 5 条承重假设按 影响 × 可能性 × 测试廉价度 排序,前 4 条都可以在本周用一次性 spike 廉价检验,且 spike 产物(引用核查器、来源探针)可直接复用为一期质量门禁,不浪费。

### Top Kill-Assumptions (ranked)

**1. 多智能体流水线能把"结论有据可查、不编造"做到可交付水平(评审修复后引用可验证率达标)**
- **Claim:** 问题计划 → 采证阅读 → 证据分析 → 报告草稿 → 评审修复 的流水线,加上横向控制 01(原文定位),能让交付报告中的关键引用在原文中真实定位;这是核心价值"专业可靠"的全部重量所在。
- **Fails if:** 评审修复后,报告中可验证引用(URL 存活且声称事实确实出现在原文对应位置)比例 < 80%,或每份报告人工修引用 > 2 小时 —— 此时产品只是"更慢更贵的通用 deep research",核心价值不成立。
- **Evidence to get this week:** 最小流水线 spike(搜索 → 抽取 → 带引用写作 → 自评审)跑 10 个真实研究问题;写一个自动核查脚本:URL 存活性 + 声称事实是否在抓取原文中出现。
- **Kill criterion:** 评审后引用可验证率 < 80%,或单报告人工修复 > 2h。
- **Cheapest test:** 上述 spike + 核查脚本(约 1 天);核查脚本保留为一期发布门禁的组件。

**2. 搜索 + 网页读取适配层能覆盖品牌/行业研究所需来源(中文来源尤其),且解析可用**
- **Claim:** 工具适配层(网络搜索、网页读取、文本/PDF 解析)能拿到品牌定位、价格、渠道、竞品与行业规模口径所需的原文;证据快照解决链接失效。
- **Fails if:** 关键来源类型(统计公报、行业报告站、电商价格页、微信公众号等)大面积付费墙/反爬/搜索索引缺失,导致多数 run 以"有限交付"收场 —— 有限交付从例外变常态,成功标准"数据口径清晰"常规性失败,产品体感是坏的。
- **Evidence to get this week:** 来源覆盖探针:为两个验收任务列 20 个典型来源类型/URL,用候选抓取栈(HTTP + readability + PDF 解析)逐个试抓取与解析,记录可达率/可解析率。
- **Kill criterion:** 必需来源类型可达且可解析比例 < 60%。
- **Cheapest test:** 探针脚本(约半天),与假设 1 的 spike 共用抓取栈。

**3. 存在愿意用独立工作台的目标用户,通用 deep research 满足不了他们**
- **Claim:** 品牌/行业研究者(咨询、投研、品牌方)的现实痛点是通用 deep research 的引用不可核、口径混用、成果不沉淀;证据抽屉、口径管理、版本化项目资产是他们会切换的理由。
- **Fails if:** 目标用户的真实工作流是"通用 deep research 跑一遍 + 人工抽查两三个数字 + 用完即弃",从不重开旧项目、不积累资产;或真实用户其实都在 JuanerAI 生态内、独立工具无分发路径(方案把 JuanerAI 集成推到三期,一期独立形态自担分发)。
- **Evidence to get this week:** 访谈 5 名品牌/行业研究者:现用工具、核引用耗时、是否重开历史研究;同时抽 3 份通用 deep research 报告人工核 30 条引用,看错误率与错误是否"肉眼可抓"。
- **Kill criterion:** 5/5 受访者核引用 < 15 分钟且从不重开历史研究,且通用产品引用抽查通过率 > 90%。
- **Cheapest test:** 30 条引用人工核查(约 2 小时)先做;访谈并行排期。

**4. 单次研究run的成本与时长在真实使用可接受区间**
- **Claim:** 横向控制 05(受控并行、调用上限、停止条件)把最坏情况框住;专业研究者可接受数十分钟级 run 与个位~数十元 API 成本(单用户自带密钥)。
- **Fails if:** 完整 run(计划 + 多轮采证 + 评审 + 复核回环)API 成本 > ¥150 或墙钟 > 3 小时且无降档旋钮 —— 真实任务使用频率趋零,成功标准沦为演示故事。
- **Evidence to get this week:** 在假设 1 的 spike 上计量每阶段 token/成本,按全流水线 5–10× 外推。
- **Kill criterion:** 外推全 run 成本 > ¥150 或 > 3h,且没有质量降档旋钮。
- **Cheapest test:** spike 内加计量(几乎零额外成本)。

**5. 一期范围能在真实预算内交付到"独立可用"**
- **Claim:** 必须实现清单 + 7 项横向控制 + 版本管理,用模块化单体可以收敛;横向控制作为横切策略而非子系统实现。
- **Fails if:** 04(检查点/取消/恢复)与 07(版本与审计)被建成完整子系统,"必须实现"清单实际是六个产品的体量;满足 5 条成功标准的最小切片仍超可用预算 2× 以上。
- **Evidence to get this week:** tracer-bullet 拆解(ISSUES 阶段本身产出),每片 t-shirt 估时,逐条映射成功标准。
- **Kill criterion:** 最小切片集估时超可用预算 2×。
- **Cheapest test:** 拆解 + 估时(拆解是流程必经步骤,边际成本为零)。

### What's Well-Reasoned

- **契约先行、JuanerAI 显式延后**:ResearchRequest / ResearchRun / ResearchResultBundle 三契约保住三期集成选项,又不让一期背上集成债;与成功标准 3 自洽。
- **"执行完成 ≠ 证据充分" + 有限交付**:把 LLM 研究产品最危险的失败模式(编造完整答案)变成显式、有依据的降级路径,是正确的产品姿态。
- **明确不包含清单**(账号/支付/多租户/插件市场/问卷投放/企业 KB):范围纪律好,一期死因大概率不在这里。
- **模块化单体、不要求微服务**:单用户本地服务形态下的正确选择。
- **横向控制 01/02/03(引用与证据、口径与逻辑、发布门禁)** 直接编码了 LLM 研究的领域性失败模式(幻觉引用、口径混用、时间/单位错配),这正是对通用 deep research 的差异化所在;若假设 1、2 的 spike 通过,这套门禁就是产品护城河。
- **证据快照 + 本地项目存储**:同时解决来源链接失效与资料保密两个真实问题。

### What I Couldn't Assess

- **需求与商业模式**:目标用户画像、付费意愿、分发路径全部未写(假设 3 只能靠访谈补)。
- **时间表 / 团队 / 预算**:未写,故假设 5 的 kill 判据目前无法数值化;ISSUES 拆解时以"最小切片集"自洽为准。
- **验收用"一项真实任务"**:品牌与行业的具体对象未指定,其资料可得性未知(与假设 2 的探针绑定,ISSUES 阶段需指定)。
- **模型 / 搜索供应商可用性**:仅举例(MiniMax / Kimi / GLM、MiniMax WebSearch);本构建环境是否有可用密钥未确认,直接决定 spike 能否真跑。
- **不可信内容 sanitization**:06 只写"来源内容不可信",网页/PDF 解析产物进模型与进证据抽屉前的清洗边界未定(PRD 需给默认值)。
