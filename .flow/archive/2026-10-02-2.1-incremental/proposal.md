# Flow Proposal: 深度研究工作台 2.1 增量升级（竞品调研 P0 借鉴点落地）

> 来源：2026-10-02 会话讨论稿 · 竞品调研沉淀于 docs/DEEP-RESEARCH-SURVEY.md（v1.0，2026-10-02）
> 基线：main @ 041856f（2.0 外部情报库已交付于 0a6b9f4；橘accent UI 契约迁移已提交）

## 一、目标（一句话）

落地竞品调研的 P0 借鉴点，让工作台从"一次性报告生成器"升级为"可增量延续的研究工作台"：

1. **P0-1 追问扩展而非重跑**：基于同一项目内已完成 run 的证据、快照、主张发起增量研究——已有证据按版本绑定复用，只对缺口采证，不重花已花过的预算与时长。
   （机制出处：Gemini `previous_interaction_id` 复用研究上下文不重跑；Kimi 同一会话追问"扩展而非从零开始"。）
2. **P0-2 执行中干预**：run 进行中允许用户提交干预指令——跳过当前问题 / 新增问题 / 修正方向 / 补充信源——编排器在采证的问题间隙消费指令队列；取消仍是兜底。
   （机制出处：OpenAI 2026-02-10 更新：实时跟踪进度并中断，中途用追加指令或新信源修正方向。）

## 三、开放问题（留给 PRD 细化与 GRILL 自答）

1. P0-1 产品形态：入口放哪（run 完成/报告页"追问"框？项目工作台发起时选"增量研究"？）；增量 run 是新 run 记录还是原 run 的延续？
2. P0-1 与 U2-06 复用流（选择器→适用性→版本绑定）的关系：run 内证据是否已具备情报库资产身份（U2-02 研究过程留档），增量研究是"自动绑定本项目 run 证据 + 用户确认"还是复用选择器？
3. P0-1 预算语义：增量 run 独立预算；报告形态（新草稿全量重装配 vs 原报告 + 增量章节）；发布版本如何演进（v(n+1) 差异摘要应能表达增量来源）。
4. P0-2 API 形态与数据结构：指令队列存哪（run 目录内文件？内存 + 落盘？）；指令类型枚举与 zod 契约；执行中 run 的指令消费时点（每问之间）；已取消/已完成 run 提交指令的行为。
5. P0-2 与检查点交互：指令是否入检查点（恢复后指令是否仍待消费）；指令生效后 run 记录如何如实呈现"用户干预过"。
6. P0-2 适用阶段边界：仅采证阶段，还是草稿/评审前也允许（如"跳过草稿直接评审"）？
7. 增量研究的 as_of 语义：沿用原 run 的截止点，还是允许刷新（刷新则旧证据需重新适用性检查）。
