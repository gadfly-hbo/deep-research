## Problem Statement

用户在现有深度研究工作台完成品牌/行业研究后，研究材料与证据只活在单个项目里：平时收集的资料散落无处安放，只有研究时才整理；开展新研究时重复寻找已取得的材料；从品牌研究扩展到行业研究时只能复用报告文字、丢失底层依据；想查证旧结论时不知道当时看了哪份材料；更新资料会覆盖旧文件、使旧报告失去解释性；只有报告的历史项目无法被诚实整理而不伪造底稿。

## Solution

在现有工作台内做增量升级（不重建研究引擎、不换技术栈）：

1. 新增**外部情报库**一级模块：文件/链接直接入库（不依赖研究任务）、整理、检索、预览、详情、加入研究。
2. 新增**共享资产与证据服务**：Source / SourceVersion / AcquisitionRecord / Evidence / Claim / Calculation / Entity / AssetBinding / UsageRecord / ReviewRecord / ResearchResultBundle 的统一读写边界。
3. **研究过程留档**：采证读取成功即保存实际材料与版本，证据随提取创建，不靠最终报告猜测底稿。
4. **跨研究复用**：检索 → 筛选 → 预览 → 人工选择 → 服务端权限与适用性检查 → 固定版本 AssetBinding。
5. **治理**：精确去重、同源转引标记、版本更正关系、生命周期（ACTIVE/ARCHIVED/WITHDRAWN）、六维状态分离（取得/核验/支持/复用范围/生命周期/任务适用性）。
6. **历史兼容**：完整底稿/部分底稿/只有报告三类迁移路径，不伪造、不破坏旧项目。
7. **成果包增量**：版本化引用、复用清单、限制与缺失说明、manifest 校验。

核心原则（proposal 已确认，不可被后续阶段推翻）：入库不等于已验证；转引不升级为已读原文；同源不算独立证据；报告是派生成果；研究绑定当时实际版本不随"最新"漂移；不伪造不越权 > 引用版本可靠 > 闭环可用 > 体验 > 自动化。

## User Stories

**直接入库（U2-01）**
1. 作为研究人员，我想不创建研究就把许可文件导入情报库，以便平时积累资料。
2. 作为研究人员，我想登记公开链接为资产，以便日后决定是否取得正文。
3. 作为研究人员，我想批量导入时逐项看到成功/重复/待确认/失败，以便处理部分失败而非被"全部完成"掩盖。
4. 作为研究人员，我想入库时看到系统提出的发布者/品牌/时期/类型候选字段并可确认或保持未知，以便不被迫填写未知信息。
5. 作为研究人员，我想登记链接不等于读取正文（状态如实区分），以便不误以为已掌握内容。

**研究沉淀（U2-02）**
6. 作为研究人员，我想研究采证读取成功时系统立即保存实际材料与取得记录，以便失败/中断的任务也保留已有效取得的材料。
7. 作为研究人员，我想证据随提取过程创建并绑定原文定位，以便报告不是保存原文的唯一触发点。
8. 作为研究人员，我想权限清楚且符合规则的来源自动进入可检索范围，敏感/归属不明/仅转引/解析有问题的保持项目范围或待处理，以便不逐条人工审批也不放任越权。

**资产列表与详情（U2-03）**
9. 作为研究人员，我想在列表看到标题/类型/对象/时期/来源/取得状态/可复用性/处理状态，以便快速筛选。
10. 作为研究人员，我想详情页分三区（原文与定位 / 元数据与版本 / 证据与使用记录），以便完整判断资产。
11. 作为研究人员，我想原文缺失必须可见，以便不把"登记了"当成"拿到了"。
12. 作为研究人员，我想"已入库/已核对/支持结论"不混成一个绿色标记，以便不被单一状态误导。

**品牌/行业整理（U2-04）**
13. 作为研究人员，我想按实体编号/类型/时期/地区/标签整理资料，以便按对象聚合资产。
14. 作为研究人员，我想同名实体先分别保留、合并需依据并可追溯，以便不被字符串相似度误合并。
15. 作为研究人员，我想品牌档案是轻量聚合页而非经营看板，以便查看关联资料与待核验信息。

**检索与筛选（U2-05）**
16. 作为研究人员，我想对有权访问的材料做关键词检索（标题/发布者/别名/类型/时期/正文）并筛选，以便找到候选资产。
17. 作为研究人员，我想看到命中片段、来源版本、日期、类型和限制，以便判断相关性。
18. 作为研究人员，我想搜索分数只用于排序、不显示为真实性概率，以便不误读。
19. 作为研究人员，我想空库时不阻断研究、索引故障时明确提示并可按列表访问，以便检索不足不卡死工作。
20. 作为研究人员，我想中文品牌/正文/英文别名/数字口径的召回经过实测，以便信任检索结果。

**加入研究与版本绑定（U2-06）**
21. 作为研究人员，我想在创建研究时搜索选择已有情报，以便减少重复取得。
22. 作为研究人员，我想系统把所选材料分为证据候选/仅作线索/需补证/权限不允许四组，以便如实使用。
23. 作为研究人员，我想确认后生成固定版本绑定（含用途与适用性说明），以便研究不随"最新版本"漂移。
24. 作为研究人员，我想选中待核验材料表示"研究这个线索"而非自动加入已确认事实，以便控制证据质量。
25. 作为研究人员，我想外发权限不足的材料不向外部模型发送正文，以便合规。
26. 作为研究人员，我想同一资料可被两个任务共用来源版本、各自有独立绑定记录，以便复用不混淆。

**去重与版本管理（U2-07）**
27. 作为研究人员，我想精确重复被识别，以便不重复入库。
28. 作为研究人员，我想同源转引被标记（人工确认），以便不把转载计为独立证据。
29. 作为研究人员，我想同一期材料的更正版与旧版本并存且旧研究仍绑定旧版并提示更正，以便历史可解释。
30. 作为研究人员，我想新时期财报是新资料对象而非旧文件升级，以便不混淆身份。

**生命周期与复用控制（U2-08）**
31. 作为研究人员，我想区分项目留档/工作台可复用/归档/撤回，以便控制资产可见性。
32. 作为研究人员，我想撤回禁止新使用并提示旧引用、归档不删除，以便安全处置。
33. 作为研究人员，我想永久删除前看到被引用项目与可保留范围并需明确确认，以便知情决策。

**历史兼容（U2-09）**
34. 作为研究人员，我想底稿完整的历史项目增量登记资产目录与版本映射，以便旧引用不失效。
35. 作为研究人员，我想只有部分原文的项目只迁移实际存在对象并记录缺失，以便诚实呈现。
36. 作为研究人员，我想只有报告的项目收录为历史派生成果并标底稿缺失，以便不伪造核验记录。
37. 作为研究人员，我想后来补齐原文记录新的取得时间而非倒填，以便历史真实。

**成果包与回归（U2-10）**
38. 作为研究人员，我想导出的成果包含版本化引用、复用清单、限制与缺失说明和 manifest 校验，以便交付一致。
39. 作为研究人员，我想未含原文的包明示"引用可追溯但接收方未必能访问"，以便不虚称完整可复验。
40. 作为管理者，我想品牌/行业双模块通过回归、失败中断部分交付状态真实，以便升级不破坏基线。

## Implementation Decisions

**沿用基线（WP00 核查确认后生效，核查发现不符时回上报）：**
- 技术栈不变：TypeScript + zod contracts、`runResearch` 唯一执行入口、适配器边界（search/fetch/parse/model 经 pi-ai 包装）、本地 HTTP server + SPA（Xanthil 三栏）、vitest 门禁。
- 现有 `contracts.ts` 已有 SourceSnapshot/Evidence/Claim/ResearchResultBundle schema —— 在其上增量扩展，不另起对象体系。
- 存储：本地元数据 JSON + 受管理文件目录（原文/快照）+ 可重建索引；不引入图数据库、独立向量服务、消息集群。

**数据契约（proposal §8.1 逻辑对象 → 落到 contracts 扩展）：**
- Source / SourceVersion（内容哈希、更正关系）/ AcquisitionRecord（授权上下文）/ Evidence（locator、口径、提取记录、revision）/ Claim（支持/反对、revision）/ Calculation / Entity / AssetBinding（run_id + 精确版本 + 用途 + as_of + 检查结果）/ UsageRecord / ReviewRecord / ResearchResultBundle。
- 六维状态枚举按 proposal §9.1；六类时间字段按 proposal §8.3。
- 存储去重不合并授权：同一内容不同 AcquisitionRecord 的权利独立。

**服务接口（proposal §12.2 逻辑契约 → 同进程方法 + server 路由）：**
- register_asset / ingest_research_source / search_assets / get_asset_version / check_reuse / bind_assets / record_evidence / change_reuse_scope / withdraw_asset / export_result_bundle。
- 权限检查点：搜索结果、片段预览、原文读取、绑定、模型上下文组装、导出六处服务端强制；禁止只在前端隐藏。

**研究流程接入点（proposal §12.4）：** 计划确认增加资产选择；读取完成即留档；证据分析绑定定位与口径；上下文组装解析授权引用；发布前核查引用闭合/版本/口径/权限；完成或中断保留有效过程资产。共享登记失败不得宣称已沉淀；无可靠底稿阻断正式发布。

**安全：** 入库 URL 服务端边界（禁本机/私网、重定向检查、体积与超时限制）；外部材料始终是数据，文档脚本/宏不执行，HTML 预览按不可信内容渲染。

**迁移：** 备份预演 → 新字段/侧表 → 旧 ID 映射 → 样本登记 → 引用权限验证 → 批次 → 兼容回归 → 用户确认切换；不破坏性覆盖；回滚关闭新入口但保留新数据。

**默认值（proposal 附录 A 空白填充，WP01/02 冻结）：**
- 用户私有导入默认 PROJECT_ONLY，跨项目复用需显式选择。
- 未知外发/导出权利默认不放行，采用限制性引用路径。

**执行编排（dev-flow 特有，proposal 未覆盖，属新增）：**
- WP00 只读核查是第一个实现切片，产出 `.flow/wp00-audit.md`（现状/缺口四分类清单、U2-01~10 与实际改动点映射、数据保护与回滚计划）。
- 范围熔断：若 ISSUES 拆解估算超 dev-flow 预算（60 轮/12h），拆分为 U2-A（入库+留档+版本绑定+检索复用闭环）与 U2-B（迁移+高级治理），拆分需用户批准。
- 冻结资料回归集（testdata/ 下固定夹具）覆盖 A-01…A-18、S-01…S-15 中可自动化部分；人工抽检项在验收报告如实标注。

## Testing Decisions

- 好测试标准：只测外部行为（接口输入输出、状态转换、门禁阻断），不测内部实现细节。
- 测试模块：资产服务（入库/去重/版本/权限/绑定纯函数核心）、server 路由薄壳、研究流程接入点（留档/上下文组装/发布门禁）、迁移脚本（三档历史样本）、检索（中文召回实测夹具）。
- Prior art：现有 `src/**/*.test.ts`（pipeline/runResearch/contracts/fsStore/attachments 等，115 测试基线）。
- 权限泄露测试：跨项目搜索的列表/计数/片段/原文/模型上下文五路断言（S-01/S-02）。
- 故障注入：半写入恢复、重复提交幂等、索引重建一致性（S-08/S-09/S-12）。
- 发布门禁：转引未升级、虚构引用、越权资料、关键计算错误的阻断断言。

- F3: `ResearchStore` 接口仅 6 方法、全部项目级——**无跨项目资产存储**，情报库需新建 workspace 级 store（本轮最大新增面）。
- F4: `server.ts` 单文件 if-chain 路由，全部 /api/* 经单一 handler——权限收口点存在（红队假设③利好）。
- F5: UI 为 `ui/{shell,views,inspector,state,components}` 无组件库；项目 DESIGN.md（Xanthil 三栏）优先于全局规范；路由 `/project/:id/:stage?`。
- F6: 无任何检索/索引基础设施——需新建（proposal 允许最小实现）。
- F7: 历史 6 项目：5 个有真实 snapshots/bundles，1 个仅 project.json+audit——迁移可走"登记级"路径，红队假设④风险低于预期。

**自答决策（均有可辩护推荐，无 proposal 冲突，无 escalation）：**
- G1 入库执行模型：小文件同步处理+任务记录；URL 取得经 fetch 适配器同步等待（带超时）；批量=逐项独立状态。取消/重试/恢复语义记录于任务状态，不引入长任务调度。
- G2 ID 方案：`s-`/`sv-`/`ev-`/`b-` 前缀+短随机（沿用 `p-`/`req-` 风格）；version_id 绑定内容哈希；evidence/claim 用 revision 整数递增。
- G3 内容哈希：SHA-256。
- G4 检索实现：新建 library 模块——元数据 JSON + 可重建关键词倒排索引（中文 bigram + 英文 token），索引文件独立、可删可重建、状态可见；不引入 SQLite/向量/新依赖。
- G5 情报库 UI：按项目 DESIGN.md（优先于全局）——侧栏新增一级入口"情报库"；列表在中央区，选中资产概要进右 Inspector；详情页三栏分区（proposal §11.3）；复用选择器嵌入研究 plan 阶段。
- G6 权限默认值：按 PRD A3（PROJECT_ONLY 默认）。
- G7 研究流程接入点：gather 读取成功→ingest_research_source；analyze→record_evidence；plan 确认后→bind_assets；publish 前→引用/版本/权限核查扩展。
- G8 导入上限：单文件 50MB、批量 20 项（WP02 实测后冻结）。
- G9 去重语义：SHA-256 精确匹配自动去重；同源候选（标题+发布者+时期近似）仅提示待确认，不自动合并。
- G10 情报库存储：`research-data/library/`（与 projects/ 平级）；不搬迁项目原文，统一引用契约。
- G11 历史迁移：登记级——扫描现有项目把 snapshots/bundle 证据登记为 Source/SourceVersion/AcquisitionRecord，引用保留原路径不搬文件；空项目标无底稿；WP05 做备份+预演。
- G12 导入解析格式：沿用 v1 已有解析器（TXT/MD/网页/PDF 基线），WP00/02 确认实际可用清单。
- G13 审计：沿用 audit.jsonl 模式，library 级独立审计流。
